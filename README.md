# Virtual Courtroom ⚖️

AI가 만든 가상 형사 사건의 배심원이 되어, 공소 투표부터 판결과 항소심까지 재판의 전 과정을 직접 경험하는 법정 시뮬레이션 웹 서비스입니다.

> **안내** 본 서비스의 사건은 모두 AI가 만든 허구이며, 실존 인물이나 사건과 관계가 없습니다. 교육과 토론을 위한 시뮬레이션이며 법률 자문이 아니고, 실제 법적 효력이 없습니다.

> **이 저장소는 직접 배포·운영할 수 있는 사람을 기준으로 만들었습니다.** Code-Name-JS는 본 서비스를 배포하거나 운영하지 않습니다. 저장소를 가져가 직접 사이트를 열어 운영해 주세요. 자세한 내용은 [배포와 운영](#-배포와-운영)을 참고하세요.

## 🎯 만든 이유

국민이 느끼는 사법 불신의 큰 원인은 재판 절차를 잘 모르는 데 있다고 봅니다. 이 프로젝트는 재판 절차를 웹에서 게임처럼 체험하면서 재판이 어떻게 돌아가는지 이해하도록 돕는 것을 목표로 합니다.

## 💡 핵심 경험

1. **입장 정하기**: 공소 제기와 불기소 중 하나에 투표하면 그 진영의 배심원이 됩니다.
2. **증거로 주장하기**: 진영 게시판에 X(구 트위터)처럼 개인 스레드를 쓰고, 자신의 생각과 그것을 뒷받침하는 증거자료를 올립니다.
3. **정보 지키기**: 증거 제출 기간에는 상대 측 게시판을 볼 수 없습니다. 정보를 흘리는 '박쥐'도 사회의 한 면으로 남겨 두되, 적발되면 제재합니다.
4. **설득의 결과 확인하기**: 비공개로 진행하는 평결 결과를 처음의 공소 투표 결과와 비교해, 어느 쪽 증거가 배심원을 설득했는지 확인합니다.

## 🏛️ 한 사이트, 한 사건

본 서비스는 **사이트 하나가 사건 하나만 다루고, 사건이 끝나면 사이트를 폐쇄**하는 단기 웹 프로젝트입니다.

- 사건은 폐기(불기소·인원 미달)되거나 판결이 확정(항소 시 2심까지)되면 끝납니다.
- 사건이 끝나면 사이트는 폐쇄되고, "이 사건은 종료되었습니다"라는 안내와 결과 요약을 담은 종료 안내 페이지만 남습니다.
- 폐쇄할 때 회원 정보는 파기합니다. 구체적인 처리는 운영자가 정합니다.

## 🧭 재판 흐름

```text
AI 사건 생성 → 공소 투표 → 공판준비 서명 → 증거 제출 → 최종 변론인 선정
→ 최종 변론 → 배심원 평결 → 판결 선고 → 리뷰(항소 신청) → 2심 결정 → 2심 배심원 모집 → 확정
→ 사이트 폐쇄
```

- 불기소가 더 많은 표를 얻으면 사건은 폐기되고 사이트가 폐쇄됩니다.
- 리뷰에 이의 신청이 있으면 운영자가 2심(항소심) 개시 여부를 결정합니다. 2심에는 1심 배심원과, 리뷰에 댓글을 달고 참여를 신청한 사용자 중 운영자가 승인한 사람이 참여합니다. 재판은 2심까지만 진행합니다.

## 🛠️ 개발과 배포

> 아래 방법은 06의 추천 기술 스택 기준입니다. 기술 스택은 배포하는 사람이 자유롭게 바꿀 수 있습니다.

### 로컬에서 실행하기

필요한 것: Node.js 24, PostgreSQL

```bash
cp .env.example .env
```

`.env`에서 `DATABASE_URL`, `SESSION_SECRET`, `IP_HASH_SECRET`(각각 32자 이상), `OPERATOR_EMAIL`을 채운 뒤 아래 명령을 차례로 실행합니다.

```bash
npm install
```

```bash
npx prisma migrate deploy
```

```bash
npm run dev
```

- `http://localhost:3000`에서 확인합니다.
- `SMTP_HOST`를 비워 두면 인증 코드 이메일이 터미널에 출력됩니다.
- PostgreSQL이 없다면 `npx prisma dev`로 로컬 개발용 DB를 띄울 수 있습니다. 이 DB는 연결을 하나만 받으므로 `DATABASE_URL` 끝에 `&connection_limit=1&pgbouncer=true`를 붙여 주세요.
- 테스트 계정을 여러 개 만들어야 하면 `.env`에서 `DEMO_MODE=true`, `DISABLE_IP_RULE=true`로 IP 규칙을 끌 수 있습니다. 실제 배포(`NODE_ENV=production`)에서는 이 설정이 무시됩니다.

### 서버에 배포하기 (Docker Compose)

1. Docker가 설치된 서버를 준비하고, 도메인이 서버 IP를 가리키도록 DNS를 설정합니다.
2. 저장소를 받은 뒤 `.env.example`을 `.env`로 복사해 값을 채웁니다. `SITE_DOMAIN`(도메인), `SITE_URL`(`https://도메인`), `POSTGRES_*`, 비밀 키, `SMTP_*`, `OPERATOR_EMAIL`이 필요합니다.
3. 아래 명령으로 실행합니다. Caddy가 HTTPS 인증서를 자동으로 발급합니다.

```bash
docker compose up -d --build
```

4. `OPERATOR_EMAIL`로 가입하면 운영자 계정이 됩니다. `/admin`에 처음 들어가면 2단계 인증(인증 앱)을 설정합니다.

**IP 규칙 주의:** 앱은 Caddy가 넣어 주는 `X-Real-IP`로 접속 IP를 판단합니다. Caddy 앞에 Cloudflare 같은 다른 프록시를 두면 모든 사용자가 그 프록시의 IP로 보여 **모두 같은 IP로 판단되고 가입이 막힙니다.** 이 경우 Caddy에 신뢰할 프록시(`trusted_proxies`)를 설정해 실제 IP를 받아야 합니다.

## 🚀 배포와 운영

- **본 서비스는 직접 배포하고 운영할 수 있는 사람을 기준으로 제작되었습니다.** Code-Name-JS는 본 서비스를 배포하거나 운영하지 않습니다.
- 저장소를 그대로 실행하면 사건 1건만 다루고, 사건이 끝나면 사이트가 폐쇄되도록 만듭니다. 다양한 사람이 각자 사이트를 열어 사건 하나씩을 진행하는 단기 프로젝트 형태입니다.
- **기술 스택은 배포하는 사람이 자유롭게 정합니다.** Code-Name-JS는 AI 플랫폼을 활용해 이 서비스의 기획을 시도했으며 기술 스택에 대한 기초지식은 없습니다. [06](docs/06-mvp-and-tech-stack.md)의 기술 스택은 추천안일 뿐이니, 자신의 판단과 권한으로 원하는 기술 스택을 사용하세요.
- 본 서비스를 잘 운영해 본 운영자라면, 운영자의 선택으로 **프로젝트를 변형하거나 2차 창작으로 이어 가기를 권합니다.** '한 사이트, 한 사건'은 설계 원칙이며 라이선스로 강제하는 제한은 아닙니다.
