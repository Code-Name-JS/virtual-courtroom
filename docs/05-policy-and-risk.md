## 제재 정책

01의 원칙(유출을 기술적으로 막지 않되 적발되면 제재)과 02의 제재 단계(경고 → 쓰기 제한 → 사건에서 제외)에 구체적인 기준을 붙입니다.

### 위반 유형별 제재

| 위반 | 판단 근거 | 처음 적발 | 다시 적발 |
|---|---|---|---|
| **유출** (자기 측 정보를 상대 측에 전달) | 워터마크 일치, 복사 글 탐지, 신고 | 증거가 명백하면(워터마크 일치 등) **쓰기 제한**, 정황뿐이면 **경고** | 사건에서 제외 |
| **유출 정보 게시** (받은 정보를 상대 측 게시판에 올림) | 복사 글 탐지, 신고 | **경고** + 해당 글 숨김 | 쓰기 제한 → 사건에서 제외 |
| **대량 유출** (게시판 전체를 캡처·수집해 넘김) | 워터마크, 비정상 열람 탐지 | **사건에서 제외** | — |
| **다중 계정 · IP 우회** (한 사람이 여러 계정 사용) | IP 변경 기록, 신고, 운영자 확인 | 관련된 **모든 계정을 사건에서 제외** | — |
| **비방 · 혐오 · 개인정보 노출** | 신고, 운영자 확인 | 글 숨김 + **경고** | 쓰기 제한 → 사건에서 제외 |

- 제재는 **사람 단위로 누적**됩니다. 위반 유형이 달라도 두 번째 제재부터는 한 단계 무겁게 적용합니다.
- 자동 탐지 결과만으로는 제재하지 않습니다. 운영자가 확인한 뒤 제재하고, 근거(신고 번호, 탐지 번호)를 기록합니다(04 `sanction`).
- 01의 원칙대로 '박쥐' 행동 자체는 막지 않습니다. 이 표는 **적발되었을 때의 결과**입니다.
- 사건에 없는 사실을 만들어 주장하는 것은 위반이 아닙니다([사건에 없는 사실도 주장할 수 있음](#사건에-없는-사실도-주장할-수-있음)).

### 이의 신청

| 항목 | 기준 |
|---|---|
| 신청 기간 | 제재를 받은 뒤 **3일 이내** |
| 처리 기한 | 운영자가 신청을 받은 뒤 **3일 이내** 답변 |
| 처리 중 | 제재는 그대로 유지 |
| 받아들여지면 | 제재 취소, 숨긴 글 복구, '사건에서 제외'였다면 참여 상태 복구 |
| 기록 | 결정과 이유를 신청자에게 알리고 04 `sanction_appeal`에 기록 |

증거 제출 기간이 1달이므로, 3일 + 3일 안에 처리하면 받아들여진 배심원이 남은 기간 동안 다시 참여할 수 있습니다.

## IP · 계정 정책

01의 "IP 하나에 계정 하나, IP가 바뀌면 이메일 인증" 규칙의 세부 기준입니다.

| 항목 | 기준 | 이유 |
|---|---|---|
| IP 변경 인증 횟수 | 계정당 **하루 5회** | 휴대폰 데이터처럼 IP가 자주 바뀌는 환경을 감안하되, 여러 네트워크를 돌며 IP를 모으는 행동은 막음 |
| 횟수를 넘기면 | 그날은 마지막으로 인증한 IP에서만 이용 가능 | |
| 인증 코드 | 6자리, **10분** 동안 유효, 5번 틀리면 새 코드 발급 필요 | |
| 이전 IP 해제 (04 질문 8) | IP를 바꾸면 이전 IP는 바로 풀어 줌 | 같은 IP가 계정 사이를 오가면 운영자에게 표시 |
| 가입 속도 제한 | 같은 IP에서 가입 시도 **하루 3회** | 계정을 대량으로 만들어 보는 시도를 막음 |
| VPN | MVP에서는 따로 감지하지 않음 | 감지 기술이 복잡하고 오탐이 많음. 다중 계정이 적발되면 제재로 대응 |
| 차단된 사용자 안내 | "이 네트워크에서는 이미 다른 계정이 이용 중입니다. 다른 네트워크에서 접속해 주세요" | 차단 이유를 알려 주되, 그 IP를 쓰는 다른 계정이 누구인지는 알려 주지 않음 |
| 운영자 계정 | 운영자도 IP 규칙을 똑같이 따름. 관리자 영역은 **2단계 인증** 권장 | 운영자 계정이 탈취되면 판결과 제재를 조작할 수 있음 |

## 개인정보 정책

01의 [개인정보 원칙](./01-service-definition.md#개인정보-동의-없이는-가능할-수-있지만-안내-없이는-안-됩니다)(별도 동의 절차는 두지 않되 개인정보처리방침은 반드시 공개, 만 14세 미만은 법정대리인 동의)에 따른 세부 기준입니다.

### 수집 항목과 보관 기간

| 항목 | 목적 | 보관 기간 |
|---|---|---|
| 이메일 | 로그인, 인증 코드 발송, 알림 | 사이트 폐쇄까지 |
| 비밀번호 (해시) | 로그인 | 사이트 폐쇄까지 |
| 닉네임 | 게시판 표시 | 사이트 폐쇄까지 |
| 만 14세 미만 여부 | 법정대리인 동의 필요 여부 확인 | 사이트 폐쇄까지 |
| 법정대리인 이름·이메일 (만 14세 미만만) | 법정대리인 동의 요청과 확인 | 사이트 폐쇄까지. 동의하지 않거나 기한이 지나면 **바로 삭제** |
| IP (비밀 키 해시) | IP 하나에 계정 하나 규칙, 가입 속도 제한 | 사이트 폐쇄까지 |
| IP 변경 기록 | 다중 계정 확인 | 사이트 폐쇄까지 |
| 이메일 인증 코드 (해시) | 가입·IP 변경 인증 | 사용하거나 만료되면 **1일 안에 삭제** |
| 열람 기록 · 워터마크 코드 | 유출 확인 | 사이트 폐쇄까지 |
| 작성한 글, 투표·참여 기록, 신고·제재 기록 | 서비스 제공, 제재 | 사이트 폐쇄까지 |

평결 내용(`verdict_ballot`)은 사람과 연결되지 않으므로 개인정보가 아닙니다.

### 만 14세 미만: 법정대리인 동의 후 가입

개인정보보호법은 만 14세 미만 아동의 개인정보를 처리할 때 **법정대리인의 동의**를 받도록 정하고 있습니다. 그래서 만 14세 미만은 부모님(법정대리인)이 동의해야만 가입할 수 있습니다.

1. 회원가입 화면(03 U-02)에서 만 14세 이상인지 미만인지 선택합니다.
2. 미만이면 법정대리인의 이름과 이메일을 입력합니다. 법은 동의를 받는 데 필요한 최소한의 법정대리인 정보는 따로 동의 없이 받을 수 있게 하고 있습니다.
3. 법정대리인에게 동의 요청 이메일을 보냅니다. 이메일에는 서비스 소개, **범죄를 다루는 가상 사건에 참여한다는 안내**, 수집 항목이 들어갑니다.
4. 법정대리인이 동의 화면(03 U-08)에서 동의하면 가입이 완료됩니다.
5. 동의를 거부하거나 **7일** 안에 응답이 없으면 가입 신청을 취소하고, 입력한 정보를 모두 삭제합니다.

- 법정대리인의 동의를 어떤 방법으로 확인해야 하는지는 법령에 정해져 있습니다. 이메일로 동의를 받는 방법이 운영자의 상황에서 충분한지는 출시 전에 법률 검토를 받아야 합니다.
- 나이는 가입자가 스스로 선택하는 방식이므로, 거짓으로 선택하는 것까지 완전히 막을 수는 없습니다.

### 파기

- 사이트를 폐쇄하면 위 항목을 모두 파기합니다(04 [사이트 폐쇄 때 파기하는 데이터](./04-data-model.md#사이트-폐쇄-때-파기하는-데이터)). 개인정보보호법은 목적을 달성한 개인정보를 '지체 없이' 파기하도록 정하고 있으며, 일반적으로 5일 이내를 기준으로 봅니다. 그래서 **폐쇄 실행 후 5일 이내 파기**를 제안합니다.
- 백업본이 있다면 백업본도 같은 기한 안에 파기합니다.
- IP 해시용 비밀 키를 먼저 폐기하면, 남아 있는 IP 해시는 되돌릴 수 없게 됩니다.

### 개인정보처리방침에 반드시 적을 내용

03의 L-02 화면에 들어갈 항목입니다.

1. 수집 항목과 처리 목적 (위 표)
2. 보관 기간: 사이트 폐쇄까지
3. 파기 시점과 방법: 폐쇄 후 5일 이내, 복구할 수 없는 방법으로 삭제
4. 개인정보를 다른 곳에 제공하거나 맡기는지 여부 (예: 이메일 발송 업체, 서버 업체)
5. 정보주체의 권리 (열람, 정정, 삭제, 처리 정지 요청)와 요청 방법
6. 개인정보 보호 책임자 연락처 (운영자)
7. 만 14세 미만은 법정대리인의 동의를 받아야 가입할 수 있다는 내용과 그 절차

## AI 사건 생성 · 검수 정책

사건은 사이트당 1건뿐이고 게시한 뒤에는 바꿀 수 없으므로, **게시 전 준비가 서비스 전체의 품질을 결정합니다.**

### 사건 만들기: AI 원본과 운영자 정리본

1. 운영자가 AI 플랫폼에 사건 생성을 부탁합니다.
2. 운영자는 AI가 만든 내용을 그대로 올리지 않고, 아래 검수 체크리스트에 맞게 **문제가 없도록 정리**합니다. AI가 만든 내용을 그대로 올리면 그 문제의 책임도 운영자가 지게 되기 때문입니다.
3. 사건 페이지에는 **운영자의 정리본을 기준**으로 보여 주고, **AI 원본도 함께 공개**합니다(03 C-01 'AI 원본 보기'). 배심원은 무엇을 어떻게 고쳤는지 직접 비교할 수 있습니다.
4. 게시와 동시에 "이 사건은 AI가 만들었습니다" 공지를 올립니다.

### 사건 유형 정하기

- 사건 유형은 정해 두지 않습니다. 운영자가 AI 플랫폼과 논의해 **간단하고 참여를 끌어낼 수 있는 유형**으로 정합니다.
- 이때 운영자가 쓰는 AI 플랫폼의 이용 정책을 따릅니다.
- 사건 내용이 미성년자(법정대리인 동의를 받은 만 14세 미만 회원)에게도 보인다는 점은 운영자가 유형을 고를 때 판단합니다.

### 게시 전 검수 체크리스트

운영자는 03 O-02 화면에서 아래 항목을 확인하고, 결과를 04 `case.review_note`에 남깁니다.

- [ ] 등장인물, 회사, 단체, 지명이 실존하지 않는지 검색으로 확인했다 (01의 '실존 인물·사건과 관계없음' 원칙)
- [ ] 최근의 실제 사건과 핵심 줄거리가 비슷하지 않은지 확인했다
- [ ] 적용되는 죄명과 형량의 범위가 실제 법과 맞다 (교육 목적이므로 법 내용이 틀리면 안 됨)
- [ ] 양측 모두 다툴 여지가 있다 (한쪽이 명백히 이기는 사건은 토론이 되지 않음)
- [ ] 사건 페이지에 "AI가 만든 사건" 표시가 있다
- [ ] AI 원본과 운영자 정리본을 모두 입력했다 (04 `case.ai_original_body`, `case.body`)
- [ ] 게시와 동시에 **"이 사건은 AI가 만들었습니다" 공지**를 올린다 (03 N-01)
- [ ] 사건을 생성한 AI 모델과 생성 일시를 기록했다

### 게시 후 수정

- 게시한 뒤에는 사건 내용을 **수정할 수 없습니다.** 배심원은 게시된 사건 내용을 바탕으로 투표하고 주장하기 때문입니다.
- 오타처럼 의미가 바뀌지 않는 정정이 꼭 필요하면, 정정 전후 내용과 이유를 공지하고 04 `case_event`에 기록합니다.

## 게시판 · 증거자료 정책

### 사건에 없는 사실도 주장할 수 있음

사건은 AI가 만든 허구임을 공지하고 공개됩니다. 배심원은 게시된 사건 내용을 바탕으로, **사건에 없는 사실을 새로 만들어 주장할 수 있습니다.** 예를 들어 "피고인이 그날 밤 CCTV에 찍혔다"처럼 사건에 없는 이야기를 더할 수 있습니다.

- 만들어 낸 이야기가 얼마나 그럴듯한지도 설득의 일부입니다. 상대 측은 그 이야기가 사건 내용과 맞지 않거나 억지스럽다고 반박할 수 있고, 최종 판단은 배심원의 평결로 드러납니다.
- 사건에 없는 사실을 만들었다는 이유로는 제재하지 않습니다.
- 다만 만들어 낸 이야기에 **실존 인물을 등장시키거나 다른 배심원의 개인정보를 담는 것**은 아래 금지 내용에 해당합니다.

### 증거자료 형식

| 형식 | 기준 |
|---|---|
| 링크 | `https` 주소만 허용, 알려진 악성 사이트는 차단 |
| 이미지 | jpg, png, webp. 1장당 **5MB 이하**, 글 1개에 **4장까지**. 올릴 때 위치 정보 등 사진 속 메타데이터(EXIF)를 지움 |
| 인용문 | 출처 필수 |
| 그 밖의 파일 | 허용하지 않음 (문서, 동영상, 압축 파일 등) |

### 저작권

- 기사, 논문, 사진 같은 다른 사람의 저작물은 출처를 밝히고 **주장에 필요한 만큼만** 인용합니다. 한국 저작권법은 출처를 밝히는 등 정당한 범위 안에서 공표된 저작물을 인용하는 것을 허용합니다.
- 기사나 글 전체를 그대로 옮기지 말고 링크와 짧은 인용을 씁니다.
- 저작권 침해 신고가 들어오면 운영자는 해당 증거자료를 숨기고 작성자에게 알립니다.

### 금지 내용

- 상대 배심원에 대한 비방, 욕설
- 혐오 표현
- 실존 인물을 사건에 등장시키는 내용, 실존 인물이나 다른 배심원의 개인정보
- 광고, 도배

위반하면 [제재 정책](#제재-정책)에 따라 글을 숨기고 제재합니다.

## 운영자 권한과 투명성

운영자는 결과를 조작할 수 없다는 01의 원칙을 지키기 위해, 운영자의 판단이 들어가는 결정에 기준을 둡니다.

| 결정 | 기준 | 공개 |
|---|---|---|
| **인원 미달** | 운영자가 판단하지 않음. 시스템이 바로 폐기 | 폐기 사유를 사건 페이지에 표시 |
| **2심 추가 배심원 승인** (02 결정 16) | 아래 참고 | 승인 기준, 진영별 신청·승인 인원, 추첨 결과 공개 |
| **최종 변론인 선정** | 진영별 1명을 **단 한 번** 선정. AI 추천과 배심원의 추천 이유를 참고. 선정 후 변경 불가 | AI 추천과 이유, 운영자 선정 결과를 공개. AI 추천과 다르게 선정하면 이유 공개 |
| 공소 제기 · 판결 선고 · 2심 결정 | 02의 기한 안에 처리 | 기한을 넘기면 사건 페이지에 "운영자 조치 지연" 표시 |
| 제재 | 위 [제재 정책](#제재-정책) | 제재 받은 사람에게 근거와 함께 통보 |
| 사건 내용 정정 | 의미가 바뀌지 않는 정정만 | 정정 전후와 이유 공지 |

### 2심 추가 배심원 승인 기준

1. **자격**: 1심 리뷰에 댓글을 단 회원이고, 이메일 인증을 마쳤으며, 제재 이력이 없어야 합니다.
2. **진영 균형**: 진영별로 **같은 수**를 승인합니다. 한쪽 신청자가 적으면 적은 쪽 인원에 맞춥니다.
3. **신청자가 많으면 추첨**: 진영별 승인 인원보다 신청자가 많으면 무작위로 추첨하고, 추첨 결과를 공개합니다.
4. **승인 인원 상한**: 사건의 최대 참여 인원(`max_participants`)을 넘지 않습니다.

운영자가 신청자 개개인을 골라 승인하지 않고 위 기준을 기계적으로 적용하므로, 한쪽 진영에만 사람을 채워 결과를 움직일 수 없습니다.

## 진행 중 생길 수 있는 상황

| 상황 | 대응 |
|---|---|
| 공소 제기 후 **불기소 측이 0명** (만장일치이거나 모두 서명하지 않음) | 불기소 측 게시판은 비어 있는 채로 진행합니다. 최종 변론은 공소 제기 측만 하고, 평결과 판결은 그대로 진행하며 판결 화면에 "불기소 측 참여자 없음"을 표시합니다 |
| **최종 변론인이 기간 안에 변론을 내지 않음** | 마감 하루 전에 알림을 보냅니다. 끝내 내지 않으면 그 진영은 "변론 없음"으로 표시하고 진행합니다. 진영 게시판은 이미 공개되어 있으므로 배심원은 게시판 내용을 보고 평결할 수 있습니다 |
| **최종 변론인 후보 추천이 0건** | AI가 그 진영에서 서명한 배심원 전체를 후보로 보고 추천하고, 운영자가 그중에서 선정합니다 |
| **AI가 변론인 추천에 응답하지 않음** | 두 번 다시 시도합니다. 그래도 실패하면 AI 추천 없이 운영자가 선정하고, AI 추천이 없었다는 사실을 공개합니다 |
| **운영자가 기한 안에 변론인을 선정하지 않음** | AI의 추천이 그대로 확정됩니다. AI 추천도 없으면 추천 표를 가장 많이 받은 후보로 확정합니다 |
| **평결 참여자가 매우 적음** | 평결은 그대로 마감하고, 판결 화면에 평결 참여율을 함께 표시합니다 |
| **운영자가 기한 안에 조치하지 않음** | 시스템이 운영자에게 다시 알리고, 사건 페이지에 "운영자 조치 지연"을 표시합니다 |
| **서버 장애로 투표·제출 마감을 놓침** | 운영자는 장애 시간만큼 해당 단계를 연장할 수 있습니다. 연장 사실과 이유를 공지하고 04 `case_event`에 기록합니다. 인원 미달과는 별개입니다 |
